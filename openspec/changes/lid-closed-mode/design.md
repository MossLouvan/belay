## Decisions (owner answers 2026-10-02: 1b 2a 3 allow-with-limit 4 part of the app)
- Platforms: macOS and Windows hosts together.
- Control: one switch in the System tab, persisted in host state (`lidClosedMode: boolean`). Only an authenticated paired device can change it.
- macOS keep-awake: `pmset -a disablesleep 1|0`. It needs root. On the first enable the host asks ONCE for an admin prompt and installs `/etc/sudoers.d/belay-lid`, which allows exactly `/usr/bin/pmset -a disablesleep 0` and `/usr/bin/pmset -a disablesleep 1` for the current user, nothing else. After that it runs `sudo -n`. If the prompt is cancelled, the switch stays off and the phone is told why. Validate the file with `visudo -cf` before moving it into place. The file is 0440 root:wheel.
- macOS lid state: `ioreg -r -k AppleClamshellState -d 4` → AppleClamshellState Yes/No, polled every 2 s only while the mode is armed.
- Windows keep-awake: save the current LIDACTION AC/DC values (`powercfg /q SCHEME_CURRENT SUB_BUTTONS LIDACTION`), set both to 0 (do nothing) + `powercfg /setactive SCHEME_CURRENT` while armed, then restore the saved values. Lid state: GUID_LIDSWITCH_STATE_CHANGE is hard from Node; simplest is to treat "no active internal panel in display enumeration" as lid closed (BelayHostDisplays already enumerates). If that's unreliable, keep the virtual display up for the whole armed stream on Windows.
- Arming: mode on AND ≥1 stream session → keep-awake on. Release: mode off, OR 30 min with no stream, OR (on battery AND ≤20%). On the battery cutoff, push a warning event to the phone ("Battery at 20% — your computer will sleep soon; plug it in"). Battery: macOS `pmset -g batt`; Windows `WMIC`/`Get-CimInstance Win32_Battery` (already used? grep osinfo.ts first).
- Crash safety: on host start, if the mode is not armed, force the release command (disablesleep 0 / restore saved LIDACTION). Also release on SIGINT/SIGTERM/exit.
- Virtual display: remove the BELAY_VIRTUAL_DISPLAY gate (keep the env var only as an explicit OFF switch `BELAY_VIRTUAL_DISPLAY=0`). When the lid closes while armed and streaming: create a virtual display at the client's requested mode via the existing route logic and switch capture to it. When the lid opens or the stream ends: destroy it and fall back to the main display. Never stack displays (the existing replace-in-place behaviour).
- App: System tab card "Lid closed" with the switch, current state (Off / Ready / Keeping awake / Stopped — battery low) and one line of help. The quality-sheet virtual display picker is no longer behind any experimental flag.
- Ponytail: no new deps; pure decision logic (`shouldArm`, `shouldRelease`, parsers for ioreg/pmset/powercfg output) lives in one small module with node tests; shell calls are thin and injected.
